# 功能建议任务流程

来源：用户安装 hueyexe/ux-usability-foundations 并要求重做交互逻辑；沿用此前单一输入、默认不采纳、预览后保存、色卡与项目隔离约束。

目标：用户在功能建议中输入想法，选择讨论或产生修改建议，看到可采纳结果，预览差异并明确保存；能认出当前阶段、失败原因和恢复路径。主要使用者是第一次或间歇使用本机项目管理器的人。

取舍：继续叠加并排按钮会保留选择负担；重做全部页面路由会扩大影响。本轮采用一个任务区、原生模式单选、一个主提交按钮；次要工具折叠，保留现有页面及后端协议。

- 已规划：默认生成修改建议，另可选择先讨论。一个有持续标签的输入框，模式说明紧邻输入，留空只允许生成建议。生成建议限3000字符，验证错误保留输入并关联控件。
- 输入在当前项目浏览器草稿中保留，刷新恢复；程序生成的规划指令不当用户输入草稿。
- 模式、输入、执行中、未保存修改均有明确状态；忙碌期间禁止重复动作；未保存时显示返回功能表入口。
- 建议结果区显示总数/选择数量，无建议、过期和未选有说明；预览禁用原因可见，生成后聚焦结果。
- 预览不写文件。功能表顶部显示当前预览及修改数量，保存按钮沿用唯一处理器；可返回建议或放弃预览。编辑过程中放弃预览不允许绕开编辑保护；失败保留预览。
- 初始项目仍从需求开始，先搜索参考，规划保存后再解锁建议；程序化拆分、生成规划和台账不被模式路由拦截。
- 保留现有粉绿风格、原生键盘控件、明显焦点、aria状态；1280×720与窄屏检验。没有用户数据迁移，不宣称模型质量提高。
