## 严重：结果与当前任务脱节，新人找不到继续入口

### U1 新增功能拆分完成后，结果不在用户发起任务的位置

**在哪：**027–036，尤其稳定状态 033。

**事实：**选择“新增功能”后，侧栏显示该项被选中。033 中当前内容却是页面顶部的 GitHub 参考卡片，未显示本次新增功能的答案或下一步。主执行者确认回复实际出现在“功能建议”的最近讨论中，随后手动点击“功能建议”，找到两条澄清问题，输入答案，再从“先讨论想法”切换到“生成修改建议”（035–036）。

**因果限制：**等待期间曾在 030 切换窄屏后还原，可能影响滚动位置。033 的画面已稳定，但不能据此断言“生成完成回调自动跳到了页顶”。本项严重判断的主要依据是新增任务回复确实位于另一个入口，必须跨模块并选择模式继续，而不是推断导致页顶位置的代码原因。

**为什么是问题：**用户只是要增加商品搜索，却必须发现结果被放到另一处、理解新增/讨论/建议三个概念，再选择内部处理模式。页面没有在本次任务原位告诉他该回答什么。第一次使用者容易以为点击没生效，重新提交或放弃。

**建议：**新增功能维持一条连续任务：输入 → 必要澄清 → 拆分预览 → 加入功能表。回答和下一步都留在同一任务区域；无需用户从“新增”转去另一个“建议”入口寻找结果或判断该调用哪个模式。

## 中等：层级和操作约定不一致

### U2 跨项目导航、项目内导航和表内操作混用，位置随滚动消失

**在哪：**003–004、016–018、020、023、025、033。

**事实：**003 有“家庭购物清单 · 项目规划”和顶栏“项目总览”；004 输入视角中两者已滚出视口。生成后 016–018 顶栏和项目名不在画面，左侧仅为“项目规划书”，主区域又出现同名标题。侧栏同时呈现新增功能、功能表与视图、功能建议、核对确认、操作记录、读取文件版本和导出动作。033 则保持“新增功能”选中，却展示 GitHub 参考列表。

**为什么是问题：**侧栏看起来像页面导航，却有的只是滚动到长页面某一段，有的是立即执行动作。用户无法稳定判断所在层级，也要滚回顶部才能退出到项目列表；跨项目时更容易忘记当前正在改哪一个项目。

**建议：**固定项目级定位，例如“项目总览 > 项目名”；项目内只保留少量同级目的地。新增、编辑、建议属于功能表内动作，放在功能表工具区。复制、导出、文件位置属于次要工具，不与页面导航共用同样层级。

### U3 进入、返回、保存和取消没有统一的空间约定

**在哪：**019–025。

**事实：**进入明细使用表格右上的“查看功能明细”，进入后页面标签却叫“功能规划与验收”，没有对应“返回清单”按钮；需要点左侧的“功能清单”页签（020–021）。编辑入口在右上；编辑状态同时有右上和左下两个“保存功能表”，取消编辑只在左下（023–024）。保存后 025 当前视口显示旧参考列表尾部和表头，刚改的行不在画面。

**为什么是问题：**用户必须为每个局部任务重新寻找退出和完成操作。同一件事的按钮重复又分散，无法形成“在这里进入，就在附近退出”的习惯；保存后内容定位变化，也很难一眼确认自己的修改。

**建议：**局部任务统一左侧返回/取消、右侧主要完成操作；固定一处任务操作栏。保存回到原行，短暂标明改动。明细与清单若是同级视图就使用一组一致命名的切换；若是进入详情，就提供明确的原路返回。

**后半补证：**051 提示“台账已保存到看板 · 10 个最细功能点”，旁边没有就地“查看看板”。主执行者需要到 052 的页首右侧点击“返回功能看板”；但新人此前从未进入过看板。这一“返回”其实是第一次进入成果页，名称与空间位置都违背当前任务的预期。

进入看板后，“项目总览”从规划页左上改到看板右上（052–053）；看板展开卡片后，056 的详情末尾没有附近的收起入口，卡片标题和全局返回均已在屏外，057 回到顶部才离开。这里的缺陷不是“保存按钮重复就必然不好”，而是取消、收起和离开没有同样就近可达的约定。历史详情 071 已有明确左上返回，可保留并统一。

### U4 功能表有多层互相重叠的视图名称

**在哪：**018–020。

**事实：**同屏存在侧栏“功能表与视图”、“表格视图/文档视图”、六个规划章节页签以及“查看功能明细”。用户眼前有“功能清单”“功能规划与验收”“功能明细”三个近义名称；查看明细后又显示正文中的“补充说明”作为第一行。

**为什么是问题：**新人先得学会产品如何分装同一份规划，才能定位一个功能的验收标准。视觉层级多，但并不对应清楚的业务层级。

**建议：**以功能清单为日常工作区，行内展开验收、技术与准备；项目目标/范围/风险归入规划说明。保留文档导出能力，但让用户少做视图选择。

**后半补证：**040 同时出现页首未保存标记、核对前请保存提示、建议预览区的未保存说明、清单内修改状态条；新增的一行功能被推到屏幕下半部。各处内容没有互相矛盾，但重复反馈占用了展示实际改动的空间。043 核对确认下仍是一整张功能表与三个同色动作，当前必须执行的步骤主要依赖阅读说明。

046 展开的核对报告直接显示 Markdown 标记、完整提交哈希和源码路径，048 的台账预览直接显示原始 Markdown。对 AI 可读的文件形式被直接暴露为新人要审阅的界面，阅读负担较大。建议主层显示人可读的核对结论和待确认项、可审阅表格；保留原文作为高级资料。

### U5 保存状态互相矛盾，用户无法确认是否还有未保存内容

**在哪：**023–024。

**事实：**主区域显示“有未保存的修改”，同时左侧仍显示“已保存 · 历史版本已保留”。

**为什么是问题：**用户离开或切换项目前，不知道该相信哪一处状态；颜色和文字各自明确，却给出相反结论。

**建议：**当前编辑状态共用一处统一状态来源。需要说明落盘基线时应明确写“上次保存于…”，不要把当前编辑和已有保存混为同一句“已保存”。

**后半补证：**051 已提示台账保存成功，052 顶部却仍仅突出“1 规划书已保存”，并提示“最终确认后，再生成功能台账”。各区域只反映自己的阶段，页面没有一致的整体完成状态。048/051 原始台账标题下仍写“目标：待规划”，与已完成规划的任务状态也不协调；这里只记录显示事实，不猜测台账生成代码原因。

### U6 GitHub 参考选择要求新人作技术判断，当前下一步又被旧主操作抢占

**在哪：**007–013。

**事实：**五张参考卡主要是英文说明、框架、许可证和星数；其中三张 IBM 卡片主要区别为 Vue.js、React、Vanilla JS。没有显示分别适合参考购物清单的哪些功能。010 中醒目的“查找参考并开始规划”仍在上方，而真正下一步“确认参考并继续”在下面屏外，011 才可见。

**为什么是问题：**新人希望借鉴“添加商品、数量、打勾、持久保存”，却要从技术框架猜哪个项目有用。完成检索后仍能看到上一步主按钮，容易再次搜索而非继续。

**建议：**每个候选先显示中文功能摘要和与当前需求的对应关系，技术资料折叠；当前步骤只突出一个下一步，把重新搜索降为次要动作。保留多选和明确不选。

### U9 窄屏只把导航和宽表堆到一起，主要任务迟迟不出现

**在哪：**稳定窄屏 075、077、079（390×844）；不采用异常截图 030。

**事实：**075 项目总览能自然按单列显示；但 077 规划页的导航从约 y=90 一直占到 y=655，当前项目名到约 y=682 才出现，首屏看不到功能表。进入表格后，079 可见的列只有序号、采用、大功能、小功能；功能介绍、验收等需要审阅的内容在横向屏外，顶部多层视图与章节选择仍占约半屏。

**为什么是问题：**手机用户先经过几乎整屏的工具目录才能到项目内容；来到表格又只能看见编号和名称，需要在横向与纵向之间来回找说明。不能仅凭此截图断言横向滚动不存在，但当前默认视口不足以完成基本审阅。

**建议：**窄屏把项目导航压缩为少量入口，主区优先展示功能；清单按层级列表显示名称与一句说明，验收和准备在行内展开，Excel 式横向表作为可选查看方式。

### U8 长任务的取消约定不一致

**在哪：**015、031。

**事实：**015 初始规划等待 103 秒，显示 50%、Codex 正在处理，没有可见取消按钮；031 新增拆分过程显示“取消本次生成”。

**为什么是问题：**阶段进度有帮助，但同样的长等待可控性不一致。用户要改需求时，不清楚应等待、离开还是取消。

- 013–015 的 50% 是处理中的阶段状态，截图名称“规划生成结果”不代表已完成；016 才有实际结果。

- 030 为视口切换后渲染异常，主执行者要求先不作为移动端产品缺陷，待稳定重测。
- 030 的视口切换可能影响后续 033 的滚动位置；033 只证明当时可见内容，不单独证明自动跳转缺陷。U1 主要依据跨入口寻找回复的实际路线。

## 建议先改顺序

1. 把发起任务、回复、澄清和下一步留在同一个位置，先消除 U1 的失联感。
2. 统一项目级定位和返回/完成操作位置（U2–U3）；这比逐个补“返回”按钮更能解决根因。
3. 统一未保存状态，并让保存后回到原行（U5、U3）。
4. 合并相近视图和术语，减少功能表上方的选择层级，并一起调整窄屏布局（U4、U9）。
5. 优化参考选择的中文功能说明和当前步骤按钮（U6）；再处理布局、目录和等待打磨（U7–U8）。

涉及取舍、需用户确定：项目内采用“功能表 / 看板 / 操作记录”的少量页面，还是维持一个长工作区；当前证据更支持前者，但本轮不擅自实现。

## 独立判断与限制

从本轮实际截图看，产品的功能链已经能够跑通，保存、预览、历史追溯和项目隔离也有可见结果；但新人体验不通过。主要负担不是按钮不够，而是项目导航、页面导航、长页面锚点、生成模式和文档结构同时要求用户理解。U1 足以让新人认为任务失效；U2–U5 则共同造成用户所说的“进出位置错乱”。

这一结论不等于源码核对判定的业务功能实现验收，也不是对所有页面的无障碍审计。第二项目只检查创建、未发送输入恢复和切换，没有再次生成完整规划；窄屏只检查总览、规划首屏、功能表三个稳定状态，没有复跑生成、编辑、保存全链；浏览器后退、键盘导航、屏幕阅读器、断网/失败重试与导出文件未在本轮独立证据中验证。不能声称这些均正常。

编号 050 对应原生保存确认，日志明确标为“实际已点击；原生弹窗无法截图”，文件字段为空，目录内没有该图；另存了浏览器确认框事件文本。因此可核对确认框文字，但不能评价其视觉排版。长任务耗时含主执行者截图、观察和工具等待，整条路线耗时不是普通用户的纯操作时间；应分开报告等待阶段与点击数。
