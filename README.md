# Markdown 项目管理器

管理多个项目的规划和功能进度。网页沿用粉绿配色、大功能包含多层子功能的卡片视图；项目资料保存在 Markdown 中，AI 可以直接阅读和更新。

## Codex 与 Claude Code 插件

提供两套自包含的本地插件，共用同一套网页和 Markdown 格式。插件包含项目管理技能与 MCP 工具：打开管理器、列出项目、读取指定项目的规划和台账。Codex 插件调用本机 Codex，Claude Code 插件调用本机 Claude Code；表格操作、版本校验、保存、导出与台账转换继续由代码执行。

```bash
python3 scripts/build_plugins.py
```

生成 `dist/feature-progress-tracker-codex.zip`、`dist/feature-progress-tracker-claude.zip` 和可安装的本地市场 `build/plugin-marketplace/`。具体安装命令与使用方法见 [插件安装说明](docs/plugins.md)。源码里的插件目录是模板，需先构建；ZIP 包包含运行文件，不依赖原仓库位置。

安装后可以说：“用项目管理器打开 `/你的目录/项目管理`，列出项目。”管理目录由用户指定，项目文件不会写入插件安装缓存。调用智能体分析前，需安装并登录对应宿主的命令行；缺少或未登录时如实报错，不自动切换到另一种智能体。同一管理目录只允许一个插件网页服务写入；切换宿主或升级后先停止旧服务再重新打开，文件保持原位。

## 启动多项目管理

需要 Python 3.9 或更新版本；规划对话另需已安装并登录的 Codex 或 Claude Code 命令行。

```bash
python3 scripts/serve_dashboard.py --workspace ./项目管理 --port 8765

# 使用 Claude Code 分析；默认 --agent codex
python3 scripts/serve_dashboard.py --workspace ./项目管理 --agent claude --port 8765
```

访问终端显示的网址，点击“添加项目”，选择“新建项目”或“导入项目”；有不同名称的台账时填写其完整路径。两种方式都先进入规划页，生成并成功保存项目规划书后才能生成功能台账、保存台账或查看看板。已有文档不会在登记时被覆盖。端口被占用时程序会选择空闲端口。

## 文件结构

```text
项目管理/
  项目列表.md                 # 指向各项目的文件路径
某个项目目录/
  项目规划书.md               # 目标、范围、阶段与未决事项
  功能执行情况.md             # 功能层级、状态、验收与证据
```

管理目录的项目清单也可以由 AI 编辑。每个项目的编号保持稳定，路径必须指向该项目目录内的 Markdown，项目文件不能彼此重叠：

```markdown
## p-example
名称：图书角
目录：/path/to/library
台账：/path/to/library/功能执行情况.md
规划书：/path/to/library/项目规划书.md
项目来源：导入项目
规划状态：待生成
```

`项目来源` 使用 `本机新建` 或 `导入项目`；新登记项目的 `规划状态` 必须为 `待生成`，由规划书生成并保存成功的流程改为 `已生成`。导入项目即使已有规划，也要结合原规划、台账和 README 重新生成，原文件保留为参考并在保存时备份。旧版登记清单没有这些字段时，仅已有有效规划书的项目可直接继续。

规划书需包含目标、范围、功能及验收的实质正文，空文件、标题或占位模板不算完成。保存失败或版本冲突不会解锁；刷新或关闭页面后，尚未保存的功能表修改不会自动恢复，请先保存，也可复制或下载保留。规划书被删除或清空后，项目会重新回到待规划状态。页面和接口都执行这一规则。

总览与看板每 3 秒读取文件。待规划项目显示“开始规划”，不计入功能进度统计；AI 修改台账后，已规划项目的进度和状态自动更新。读取失败会明确显示错误。统计按最细功能点计算，不重复计算父功能。

规划页首次提出需求后，先由所选智能体提取英文关键词，通过 GitHub 公开接口搜索相似项目并读取部分 README，再生成初步功能表。仓库卡片支持多选；点击“保存参考选择并继续”，后续规划只引用所选仓库。也可明确不选任何仓库；重新搜索后需要重新确认。仓库只作功能参考，不会自动克隆或采用代码。可修改关键词重搜；零结果明确展示，失败时先重试，不伪造调研来源。公开接口限额可能使检索暂时不可用。调研记录保存为项目目录中的 `GitHub参考项目.md`，后续对话会读取已保存的参考选择。

每次网页成功保存规划书或功能表，都会在项目的 `规划历史/` 中归档一份独立 Markdown，包括保存时间、修改来源、可选说明及当时的参考项目。在“操作记录”中点击“查看当时功能表”可查看旧功能表、与上一版的正文差异，并下载该版 Markdown 或 Excel；历史查看及导出保持只读。首次保存会同时归档已有的有效规划文件；外部 AI 修改在下一次网页保存前捕获，不能追补升级前每次保存的全部历史。归档失败会报告保存失败并恢复原文件，待规划项目保持未解锁。

“编辑功能表”可直接修改标准编号表的名称、层级、说明、验收、技术和前期准备，并保存回 Markdown；表外内容和未知列保留，保存前校验版本并备份。旧的非标准规划可先通过“生成／更新规划书”整理为标准表再编辑。调整上级时，编号前缀及依赖也须同步。未保存的功能表修改只保留在当前页面，离开或刷新前会提示保存；不再自动暂存或提供草稿恢复。冲突时保留页面中的修改，先核对最新文件。

功能清单的“采用”默认全选，取消代表不采用，勾选与开发完成无关。取消父项会连同子项取消；选中子项恢复祖先。取消项仍保留在规划和 Excel 中，不新增为实施任务；既有台账历史保留。主清单改变选择后点击“保存规划书”，或在编辑表中点击“保存功能表”，再继续对话或生成台账。

“引导拆分新功能”先讨论使用者、边界、验收、所需技术及前期准备，每轮只澄清少量关键问题。建议不直接写入项目；确认后用“生成／更新规划书”合并，沿用编号和用户已取消的采用选择。点击“生成功能台账”后审阅结果，再“保存到看板”；替换仍需确认。清空聊天不会删除项目 Markdown。

保存台账前会预览按实际最细功能计算的进度。如果页首明确的进度摘要与功能结构不一致，确认框会列出校正内容；保存后另存 `*.generated-source-*.md` 保留校正前的提交原文。功能验收、业务数字和历史说明不会作为进度摘要修改。问题与争议的标记由服务统一判断，纯粹表示没有问题的描述不会计入问题数。

规划书支持标题、表格、引用、有序和无序列表以及代码块。Markdown 中的 HTML 和链接仅作为文本展示，不执行代码或加载外部资源。

规划页默认打开“功能清单”，参考按列分层的清单形式，将大功能、小功能、细分功能和功能介绍放在不同列，同一父项的连续记录纵向合并；深于三级继续增加层级列。有明确金额资料时才显示“大概金额”。父项自身说明保留，验收、优先级、依赖和备注仍可在原功能明细表查看。清单行数包含父项说明，不是完成率。

各章节可切换工作表；点击“查看功能明细”可进入原功能表，按箭头逐级展开，也可全部展开、收起层级或切换到文档视图。已有标题、粗体编号、列表和表格混合的规划仍可查看；未明确的优先级、依赖等字段保持空白。

点击“下载 Excel”可导出当前页面的规划，包括未保存草稿。真正的 `.xlsx` 默认打开带项目标题与纵向合并单元格的功能清单，并包含各章节、冻结表头、层级大纲、自动换行和完整的“规划原文”工作表。导出仅生成副本，不代表规划已保存或流程已解锁；修改 Excel 不会回写 Markdown。项目文件仍是 AI 与网页共享的事实来源。新生成的功能规划使用“编号、上级编号、功能名称、说明、验收标准、优先级、依赖、备注”分列，包含关系和依赖分别记录。

## AI 更新约定

- 先读项目规划书及已有台账，保留稳定编号、历史记录和审核证据。
- 使用 `## 大功能 F01：名称`、`- [ ] F01-01 名称｜状态：进行中`，细项使用 `F01-01-01`。
- 字段使用缩进列表；支持 `验收：…` 和 `**验收**：…`。
- 实施、受阻、审核及需求变化时同步状态、证据和问题。变更已验收功能时保留旧记录并新增关联项或重新审核。
- 网页不会自动审核功能；完成条件见 [SKILL.md](SKILL.md)。

## 兼容单项目

```bash
python3 scripts/serve_dashboard.py examples/功能看板示例.md --port 8765
```

示例是虚构数据。单项目模式同样要求台账目录中有有效的 `项目规划书.md`，否则先进入规划页；它不提供多项目登记，需要多项目时使用 `--workspace`。
