## 按严重程度列出的遗留问题

本轮未发现阻断主流程的严重问题。

1. **中等：没有选参考仓库，也记录“已读取固定提交”。** 位置：规划页操作记录，[截图 20](host-chat-retest/browser/20-source-record.png)。同一时间线明确记录“选作参考：明确不选”，随后却显示已读取固定提交。包测试该场景确实为空参考。会让用户误以为已有源码核对依据。应按实际来源数量区分“无参考仓库”与“已读取源码”；不能用通用成功文案代替事实。独立核对对应 `project_service.py:406` 的无条件记录。**F09-04 的“展示实际结果”不再满足，转待审核，原审核与证据保留。** 没有发现该文案错误绕过源码绑定或写入保护。
2. **中等：深层子功能被父项详情压到下一屏以后。** 位置：看板，[截图 12](host-chat-retest/browser/12-parent-details.png)、[截图 13](host-chat-retest/browser/13-nested-details.png)。1280×720 下父标题位于页面 y=430，子标题位于 y=1205，相隔 775 像素；展开后页面高 2,110 像素，子卡片只有 303 像素宽。用户需要经过状态、验收、技术、审核等约 12 组字段才能找到下一级。建议子功能入口优先展示，父项完整详情按需展开。记入既有 F09-07，不撤销层级与统计通过结果。
3. **轻微：内部名称和文件路径占据用户界面。** 位置：[截图 19](host-chat-retest/browser/19-raw-error-name.png)显示 `save_plan 失败`；[截图 16](host-chat-retest/browser/16-live-sync.png)的项目路径跨三行。失败后的中文原因与恢复提示存在，未阻断操作，但首次使用者需要理解内部词和长路径。建议显示“保存规划失败”，路径折叠到文件位置。记入 F09-07。

建议顺序：先修记录真实性，再替换内部用语，最后调整深层详情展开结构。独立 Agent `/root/retest_core` 实际读取截图、核对代码及 F09-04 验收标准后确认上述范围；截图复核不冒称其亲自执行浏览器操作。

## 结论范围与限制

- 自动化与 R1–R5 的独立限定审核 97/100（40/29/18/10）；包、协议、升级限定审核 94/100（40/28/17/9）。分数不覆盖本轮发现的记录文案违约，也不代表所有用户体验通过。
- 本机找不到 Claude CLI。两套 ZIP 的真实 stdio 测试不等于真实 Claude Code 安装和自然语言会话；F11-01 继续待审核。本轮也没有新增 Codex 模型自然语言会话验证。
- 建议与进度测试中的实施者、审核字段为明确夹具，不冒称图书项目已经开发或独立验收。联网来源的静态核对不等于执行参考项目。
- 未验证原生 Excel、屏幕阅读器、手机真机、长期并发、已经超限的历史大文件。网页仍采用现场环境时区，原始截图显示执行环境时间。
- 源码测试脚本最初错误地要求 `--no-checkout` 克隆工作树干净，纠正该测试假设后重新校验了浅克隆和实际 blob；这不是产品故障。截图采集 01、15 不完整、一次定位重试、系统 Python 缺少 Pillow 后改用已有捆绑运行时生成总览，均未当作产品缺陷。
- [联网脚本](host-chat-retest/github/run_stdio_live_test.py)和证据中的临时路径是当次运行记录；重跑应创建新的隔离目录，不直接复用旧业务状态。

台账本轮保留 R1–R6、F12 技术范围通过，F09-04 重新打开为待审核：已验收由 43/46 调整为 42/46（91.3%），待审核 3，未开始 1。
