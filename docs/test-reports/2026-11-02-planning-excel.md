# 规划层级表格与 Excel 验证

日期：2026-11-02。需求：项目规划以 Excel 风格表格呈现，且同时支持网页表格与真正的 Excel 文件下载；保留 Markdown 供 AI 读写。

## 本轮实现

- 网页默认打开功能规划工作表，各章节可切换；功能用编号、缩进和展开/收起表现包含关系。
- 功能表分列展示名称、说明与验收、优先级、依赖和备注；未提供的数据不推断。文档视图保留原有 Markdown 阅读方式。
- 新生成规划要求八列 Markdown 功能表，明确上级编号与依赖的区别；兼容旧标题/列表/粗体编号/子表格。
- 页面和 Excel 共用解析模型；导出当前页面内容（含草稿），不改文件、规划状态或台账，不能代替保存规划书。
- Excel 按章节分工作表，保留冻结表头、自动换行、层级大纲与粉绿配色；完整 Markdown 在“规划原文”表保留。文本不会被作为公式执行。

## 验证证据

Python 与前端测试包括：标准表三级层级，父行乱序、重复/缺失/循环父编号，旧规划投影，代码与转义管道，Excel包结构/冻结/大纲/长文本/原文换行/公式安全，HTTP项目隔离及不写文件，规划有效性与先规划门槛；前端异步响应乱序、草稿导出、导出失败、原文回退、折叠与切换状态。

独立审核对两个历史真实规划逐项检查：图书规划48个正文块、摄影规划96个正文块均保留；图书保留“借阅办理→借出→4个校验子项”，摄影保留F01—F04及子项。规划表格行包括说明行，不能等同于功能台账叶数。

浏览器使用 CUA 在临时只读服务展示现有图书规划，验证默认功能表13行；收起层级后5行，展开借阅办理7行，再展开借出11行。文档视图仍可读到原四级标题，切回表格保留折叠状态；风险章节切换成功，9行资料完整。

实际点击下载按钮产生 .xlsx，使用 bundled @oai/artifact-tool 导入并 inspect 8个工作表，渲染功能规划 A1:F10 后人工查看，说明列可读、无明显裁切。下载副本与预览在工作区 outputs/规划表格验证，原项目Markdown未因读取和下载发生修改。

## 边界

本轮没有新增真实模型调用；沿用历史真实规划和受控生成回复做兼容回归。基础规划校验不代替业务审核。Excel是只读导出副本，本轮不支持Excel修改回写。工作簿已通过包结构、导入与渲染验证，未在桌面Excel客户端执行交互操作。标准Excel大纲深度上限7，深层完整内容仍保留。
