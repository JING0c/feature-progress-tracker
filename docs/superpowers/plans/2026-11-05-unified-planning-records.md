# 规划记录统一入口实施计划

**Goal:** 用户从操作记录看清何时做了什么，并可打开该次保存的完整功能表。
**Architecture:** 复用已有活动时间线与不可变快照，以快照ID精确关联。保留独立文件和既有只读接口，网页只提供一个记录列表，详情是列表的子视图。
**Tech Stack:** Python标准库、原生JavaScript和CSS。

## 短设计

用户认为历史版本和操作记录重复，内部编号无法理解，也不知道版本如何产生。采用统一操作记录入口：时间、操作结果、改动摘要；保存记录附“查看当时功能表”，详情注明保存原因、只读及返回记录。旧快照单独标明早期记录缺少日志；保存前自动归档时间不能冒充原修改时间。无对应快照的普通讨论/失败不显示查看按钮。保留原始Markdown、快照完整内容和Excel/Markdown导出。

另一方案是保留两份列表仅改名，能减少代码变化但仍要求用户分辨重复记录。用户已明确选择统一入口：合并到操作记录，点击“查看当时功能表”。

## 约束与复验重点

- 精确按 history_version 关联，不能按同内容、同时间推测；已有保存和兜底历史不重复。
- 只读展示不触发新记录、保存、模型或覆盖当前草稿；不存在的快照不显示可用入口。
- 较晚返回的详情不能覆盖新选择或“返回记录”；读取失败不残留错误版本的下载按钮。
- 原6份快照和日志全部保留；导出仍指向用户选中的旧表。
- 1280×720和窄屏检查入口、返回与长标题；用隔离项目实际点击并对比文件hash。
