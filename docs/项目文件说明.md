# 项目文件说明

本说明对应 Markdown 项目管理器及其 Codex、Claude Code 插件。文件名相同但所在目录不同，可能代表不同项目；判断时先看完整路径。

## 先分清三个位置

| 位置 | 放什么 | 谁使用 |
|---|---|---|
| 程序源码目录，例如 `protuct_plan/` | 网页、Python 代码、插件模板、测试、开发文档 | 需要修改这个管理器的人和 AI |
| 管理目录，由打开管理器时的 `--workspace` 指定 | `项目列表.md`，以及插件服务的运行状态 | 项目管理器，用来找到各个项目 |
| 每个项目自己的目录 | 该项目的规划书、功能台账、参考资料和操作记录 | 用户、AI、该项目的看板 |

管理目录相当于项目通讯录，`项目列表.md` 记录每个项目在哪里。导入项目继续使用原来的目录，不会自动复制到管理目录。新建项目没有填写目录时，才默认放在管理目录的 `项目/名称-随机码/` 下。

建议把管理目录放在源码目录之外，例如 `~/Documents/项目管理/`，便于分别备份和管理 Git。程序不会自动把所有业务 Markdown 排除出 Git；是否提交业务资料，按各项目自己的规则决定。

```text
程序源码目录/                         ← 开发这个管理器
  README.md
  scripts/
  plugins/
  项目规划书.md                       ← 管理器自身的开发规划
  功能执行情况.md                     ← 管理器自身的开发进度

用户指定的管理目录/                   ← 打开插件时指定这里
  项目列表.md                         ← 登记下面两个项目的位置
  .feature-progress-tracker/          ← 插件运行状态，不是业务进度
  项目/
    记账工具-随机码/                  ← 聊天工具默认新建的位置
      项目规划书.md
      功能执行情况.md

已有的网站项目目录/                   ← 从原目录导入，不搬家
  项目规划书.md
  功能执行情况.md
  原有代码和其他文件
```

以上是位置示意，不代表程序已经在你的电脑上创建了这些示例项目。实际路径以管理目录的 `项目列表.md` 为准。

## 源码仓库里的文件

| 文件或目录 | 用途 | 什么时候看或改 |
|---|---|---|
| `README.md` | 项目入口、启动方法和文档导航 | 第一次打开仓库先看它 |
| `docs/项目文件说明.md` | 本文：目录、数据文件与安装包的用途 | 不知道文件放哪、由谁生成时查 |
| `docs/plugins.md` | 两种插件安装、切换、停止和更新方法 | 安装或排查插件时看 |
| `SKILL.md` | AI 管理规划与台账的规范，包含独立审核规则 | AI 接手项目管理工作时读；规范变化时更新 |
| `项目规划书.md` | **这个管理器本身**的需求、设计和变更历史 | 开发管理器时更新，不用它代替业务项目的规划书 |
| `功能执行情况.md` | **这个管理器本身**的实现、测试与独立审核进度 | 管理器开发或审核有进展时同步，不把新项目登记到这里 |
| `scripts/` | 实际运行的 Python 服务、网页、JavaScript 和样式 | 修改功能或页面时改这里的源文件 |
| `plugins/` | 两种宿主的插件模板和共享流程说明 | 修改插件清单、技能说明时改；需构建后安装 |
| `.agents/plugins/marketplace.json` | 源码中的 Codex 本地市场入口 | 指向构建后的 Codex 插件 |
| `.claude-plugin/marketplace.json` | 源码中的 Claude Code 本地市场入口 | 指向构建后的 Claude Code 插件 |
| `tests/` | 自动回归测试；`fixtures/` 是固定测试材料 | 修改逻辑后验证；不存业务项目数据 |
| `examples/功能看板示例.md` | 虚构的层级功能台账示例 | 参考格式；不代表真实功能已经完成 |
| `docs/test-reports/` | 测试结果、独立审核和已知验证限制 | 查某次改动实际验证到哪一步 |
| `docs/ux/` | 用户体验走查及修补记录 | 查交互问题和改动依据 |
| `docs/superpowers/` | 较早开发轮次的设计与执行计划 | 查设计过程；以最新需求和代码核实当前行为 |
| `.gitignore` | 排除构建输出、运行缓存、密钥和部分备份文件 | 增加新的本地产物时维护 |
| `build/`、`dist/` | 构建得到的插件目录和 ZIP | 分发或安装时使用；不要直接修改其中的程序副本 |

源码目录中的项目规划和台账属于本工具的开发记录，不会因启动管理器就自动成为一个已登记业务项目。`build/`、`dist/` 被本仓库 Git 忽略，重新克隆源码后需要构建；已有成品ZIP可直接解压安装。

### 要改某项功能，找哪些源文件

以下路径均相对于源码仓库，不是相对于业务项目目录。

| 要处理的内容 | 主要文件 |
|---|---|
| 只读网页服务、项目存储与保存门槛 | `scripts/serve_dashboard.py` |
| 对话中的项目操作、版本保护和跨进程锁 | `scripts/project_service.py` |
| 进度更新、独立审核与重开保护 | `scripts/project_progress.py` |
| 项目总览、规划页、功能看板 | `scripts/projects.html`、`scripts/planning.html`、`scripts/dashboard.html` |
| 表格解析、字段编辑与层级校验 | `scripts/planning_sheet.py`、`scripts/planning_editor.py` |
| 新增提案合并、台账转换等代码操作 | `scripts/planning_operations.py` |
| AI 分析 | 当前 Codex / Claude Code 会话或其真实子智能体；不由网页后台调用 |
| 功能建议的数据与采纳预览 | `scripts/planning_suggestions.py`、`scripts/planning-suggestions.js` |
| GitHub 搜索与参考资料、源码读取 | `scripts/planning_research.py`、`scripts/planning_source.py` |
| 保存快照与操作记录 | `scripts/planning_history.py`、`scripts/planning_activity.py` |
| Excel 文件导出 | `scripts/planning_xlsx.py` |
| 阶段进度与等待反馈 | `scripts/planning_progress.py`、`scripts/plugin_mcp.py`（MCP 阶段通知） |
| 表格、文档及记录的前端显示 | `scripts/planning-sheet-view.js`、`scripts/planning-markdown.js`、`scripts/planning-activity.js` 及相应 CSS |
| 插件打开、查询、停止本机服务 | `scripts/plugin_manager.py` |
| 插件的完整对话工具及参数合同 | `scripts/plugin_mcp.py`、`scripts/project_tools.py` |
| 把源文件组装成可安装的插件包 | `scripts/build_plugins.py` |

AI 分析调用和文件操作分开：分析给出建议，修改功能表、合并、保存、转换及导出由代码执行。改变运行代码后要重新构建插件；修改已安装缓存里的副本不会回写源码。

## 每个业务项目会有哪些文件

这些文件位于该项目的目录，不一定在管理目录内。除登记时创建的占位规划书与默认台账外，其他文件通常在使用对应功能后才出现；已有文件不会在登记时被覆盖。

| 文件或目录 | 保存什么 | 何时产生或更新 | 修改方式 |
|---|---|---|---|
| `项目规划书.md` | 目标、范围、分层功能表、验收标准、技术、准备和未决事项 | 新建或导入先创建缺失的占位文件；规划生成并保存后写入有效正文，后续保存功能表继续更新 | 通过对话中的save_plan/edit_features工具更新，保留版本、编号和其他章节 |
| `功能执行情况.md` | 进入实施的功能、状态、实施证据、审核人和评分 | 缺失时创建占位台账；“保存到看板”及后续实施跟踪时更新 | 通过save_ledger/update_feature_progress工具维护；完成勾选需独立审核 |
| `GitHub参考项目.md` | 调研结果、仓库资料与用户保存的参考选择 | 搜索和保存参考选择时 | 通过参考区更新；保留其结构化内容 |
| `功能建议.md` | 针对某一规划版本生成的结构化修改建议 | 生成建议时 | 在对话中选择、预览和保存；这个文件的存在不表示建议已采纳 |
| `规划源码核对.md` | 已选参考仓库的源码依据、提交及核对结果 | 执行源码核对时 | 重新核对生成，不手改它来冒充已通过核对 |
| `规划操作记录.md` | 操作时间、类型、实际结果及修改信息 | 执行受记录的规划操作时 | 在“操作记录”查看；含程序使用的结构，不作为自由笔记编辑 |
| `规划历史/v-*.md` | 保存当时的规划正文、参考项目及版本元数据 | 聊天工具成功保存时归档；首次或外部有效版本可能在保存前另行归档 | 从操作记录打开“查看当时功能表”；保持只读，正文有摘要校验 |
| `.reference-code/仓库所有者--仓库名/` | 参考仓库的 Git 源码缓存 | 最终源码核对需要时浅克隆 | 供程序按提交读取，不执行参考代码；可能没有普通的检出源码文件 |
| `*.backup-*.md` | 已存在文档被覆写前的原内容副本 | 采用文档备份写入流程时，在原文件旁生成 | 用于排查和恢复，不把它登记为主台账 |
| `*.generated-source-*.md` | 校正台账进度摘要之前提交的原文 | 保存台账且确实发生进度摘要校正时 | 留作核查，不替代当前台账 |

台账可以使用用户指定的其他 Markdown 文件名，具体看 `项目列表.md` 的“台账”字段。占位文件存在不代表规划完成；新建和导入都要先完成有效规划书保存，再进入后续台账与看板流程。

“操作记录”和“历史功能表”有关联，但用途不同：前者回答**做了什么**，后者保留**当时整张功能表是什么样**。界面把它们放在同一个入口中，文件仍分别保存。

### 不在这些 Markdown 文件里的内容

| 内容 | 实际位置和行为 |
|---|---|
| 规划聊天、需求讨论与分析 | 当前Codex/Claude Code宿主会话；网页不保存或读取聊天。要备份完整对话请使用宿主自身的会话功能 |
| 尚未保存的功能表或采纳预览 | 工具返回到当前对话中的候选内容；明确保存后才落入当前规划，预览记录不等于保存 |
| 导出的 Excel、Markdown | 聊天export_project写入项目exports目录的唯一新文件；网页下载则在浏览器下载位置。Excel不回写规划书 |

## 管理目录中的运行文件

| 文件 | 作用 |
|---|---|
| `项目列表.md` | 登记项目编号、名称、目录、规划书路径、台账路径和规划状态；它本身不包含各项目的全部资料 |
| `.feature-progress-tracker/dashboard.json` | 插件启动服务的身份、地址、宿主与运行版本信息；不是功能进度；正常停止后删除 |
| `.feature-progress-tracker/dashboard.lock` | 避免启动、停止操作互相冲突 |
| `.feature-progress-tracker/service.lock` | 限制同一管理目录只有一个插件服务写入；锁文件留下不代表服务仍在运行 |
| `.feature-progress-tracker/codex-*.log`、`claude-*.log` | 本地网页服务的运行日志，用于排查启动和请求错误 |

workspace和每个项目目录中还可能存在 `.feature-progress-tracker/operations.lock`，由聊天工具用于跨宿主/跨管理目录写入串行；管理目录还保存源码核对准备票据。运行状态目录由插件维护。服务运行时不要手动删除状态或锁文件；需要清理时先按[插件说明](plugins.md#切换宿主与停止服务)停止服务。停止后锁文件和日志仍可能保留，清理它们不会删除已经保存的业务 Markdown。直接在终端启动传统网页服务时，不一定存在这些插件运行文件。

## 三个 ZIP 该用哪一个

| 构建产物 | 包含什么 | 用途 |
|---|---|---|
| `dist/feature-progress-tracker-marketplace.zip` | 两种插件及各自市场清单 | **第一次安装或发给别人，优先用这个。** 解压后按安装说明注册市场 |
| `dist/feature-progress-tracker-codex.zip` | 独立 Codex 插件，含运行代码和说明 | 加入已有本地市场；不能把这个 ZIP 当作市场目录传给 `marketplace add` |
| `dist/feature-progress-tracker-claude.zip` | 独立 Claude Code 插件，含运行代码和说明 | 解压后临时加载，或加入已有市场 |

这三个 ZIP 都是软件，不包含你的业务项目。`build/plugin-marketplace/` 是完整市场解压前的目录形式，源自 `plugins/` 模板与 `scripts/` 代码。不要直接安装源码中的 `plugins/codex/` 或 `plugins/claude/`，那里尚未包含完整运行文件。

单个成品插件的主要内容如下；拿到源码时不会在模板里看到所有这些目录：

```text
插件根目录/
  README.md                              使用入口
  .codex-plugin/plugin.json              Codex 兼容清单，仅 Codex 包
  plugin.json、mcp.json                  Codex portable 清单，仅 Codex 包
  .claude-plugin/plugin.json             Claude Code 清单，仅 Claude 包
  .mcp.json                             本地工具启动配置
  skills/project-manager/SKILL.md        宿主会话中的项目管理技能
  skills/project-manager/references/     共享工作流程
  runtime/SKILL.md                       详细功能台账与独立审核规范
  runtime/scripts/                      自包含的服务与网页程序
  runtime/docs/                         随包附带的安装和文件说明
  package-inventory.json                包内文件的 SHA-256 校验清单
```

成品插件中的 `runtime/` 是构建副本。宿主可能更新或替换整个插件缓存，因此业务资料始终放在用户指定的目录。安装、宿主切换和停止的完整命令见[插件安装说明](plugins.md)。

## 备份与交接时带哪些文件

- **备份业务项目：**保存管理目录的 `项目列表.md`，再保存其中每个项目实际目录的规划书、台账、参考、建议、核对、操作记录及 `规划历史/`。导入目录可能在管理目录外，只复制管理目录会漏掉它们。
- **需要完整聊天：**使用Codex/Claude Code自身会话导出功能。完整宿主聊天不在Markdown项目备份中。
- **迁移电脑或目录：**文件迁移后核实登记中的路径。绝对路径不会因为复制而自动改成新位置。
- **保留历史依据：**规划历史和操作记录应一起保存；重要的备份及原始提交副本也可保留。不要把历史快照当成当前版本覆盖回去而不检查差异。
- **清理参考缓存：**`.reference-code/` 可重新获取，但清理或改变缓存后需重新源码核对；不要假定旧报告仍有效。
- **交给别人安装工具：**发送完整市场 ZIP 和安装说明。对方安装的是工具；如需交接业务资料，应另行提供对应项目文件。

管理器本身的开发完成情况看源码根目录的 `功能执行情况.md`；某个业务项目的完成情况看该项目登记的台账。插件“已打包”与真实宿主、模型流程“已验证”也分别记录，具体证据见源码中的 `docs/test-reports/`。
