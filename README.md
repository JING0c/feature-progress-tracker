# Markdown 项目管理器

管理多个项目的规划和功能进度。网页沿用粉绿配色、大功能包含多层子功能的卡片视图；项目资料保存在 Markdown 中，AI 可以直接阅读和更新。

## 启动多项目管理

需要 Python 3.9 或更新版本；规划对话另需已安装并登录的 Codex 命令行。

```bash
python3 scripts/serve_dashboard.py --workspace ./项目管理 --port 8765
```

访问终端显示的网址，点击“添加项目”。可输入现有项目目录，也可以创建新目录；有不同名称的台账时填写其完整路径。已有文档不会在登记时被覆盖。端口被占用时程序会选择空闲端口。

## 文件结构

```text
项目管理/
  项目列表.md                 # 指向各项目的文件路径
某个项目目录/
  项目规划书.md               # 目标、范围、阶段与未决事项
  功能执行情况.md             # 功能层级、状态、验收与证据
```

管理目录的项目清单也可以由 AI 编辑。每个项目的编号保持稳定，路径必须指向该项目目录内的 Markdown，项目文件不能彼此重叠：

```markdown
## p-example
名称：图书角
目录：/path/to/library
台账：/path/to/library/功能执行情况.md
规划书：/path/to/library/项目规划书.md
```

总览与看板每 3 秒读取文件。AI 修改台账后，进度和状态自动更新；读取失败会明确显示错误。统计按最细功能点计算，不重复计算父功能。

规划页根据所选项目的文件和对话进行梳理。点击“完成对话，生成规划书”后，规划书会显示并保存为 Markdown。点击“生成功能台账”后审阅结果，再“保存到看板”。保存前检查版本并保留备份，文件冲突时保留草稿。浏览器中的对话按项目保存；清空聊天不会删除 Markdown 文件。

保存台账前会预览按实际最细功能计算的进度。如果页首明确的进度摘要与功能结构不一致，确认框会列出校正内容；保存后另存 `*.generated-source-*.md` 保留校正前的提交原文。功能验收、业务数字和历史说明不会作为进度摘要修改。问题与争议的标记由服务统一判断，纯粹表示没有问题的描述不会计入问题数。

规划书支持标题、表格、引用、有序和无序列表以及代码块。Markdown 中的 HTML 和链接仅作为文本展示，不执行代码或加载外部资源。

## AI 更新约定

- 先读项目规划书及已有台账，保留稳定编号、历史记录和审核证据。
- 使用 `## 大功能 F01：名称`、`- [ ] F01-01 名称｜状态：进行中`，细项使用 `F01-01-01`。
- 字段使用缩进列表；支持 `验收：…` 和 `**验收**：…`。
- 实施、受阻、审核及需求变化时同步状态、证据和问题。变更已验收功能时保留旧记录并新增关联项或重新审核。
- 网页不会自动审核功能；完成条件见 [SKILL.md](SKILL.md)。

## 兼容单项目

```bash
python3 scripts/serve_dashboard.py examples/功能看板示例.md --port 8765
```

示例是虚构数据。单项目模式不提供多项目登记，需要多项目时使用 `--workspace`。

## 验证

```bash
python3 -m unittest discover -s tests -v

# 有 Node.js 时可单独运行前端行为回归（无第三方依赖）
node tests/test_markdown.cjs
node tests/test_planning_save.cjs
```

服务只监听本机；无需 Python 第三方依赖。服务停止后页面不能更新，已保存的 Markdown 仍在。
