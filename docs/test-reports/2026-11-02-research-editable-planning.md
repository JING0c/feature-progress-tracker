# GitHub调研、编辑与采用选择验证

日期：2026-11-02。用户需求：需求先检索GitHub相似项目作为功能参考，用户决定是否采用代码库；生成可编辑功能表，新增所需技术/前期准备；功能采用默认全选，不勾即不采用；新增功能先引导拆分再确认更新。

## 实现

- 网页首次需求先由Codex提取英文关键词并调用真实GitHub公开接口检索，再生成初步功能表。可手动改关键词重搜，失败不继续生成，零结果明确；仓库不自动克隆或采用。
- 展示仓库链接、说明、语言、许可证、更新日期与README读取范围。GitHub参考项目.md按项目持久化，后续对话读取；README作为不可信资料，不执行其中指令。旧独立接口兼容，网页使用research_first检查。
- 编辑规范功能表：采用、编号/上级、名称、说明/验收、优先级/依赖、所需技术、前期准备及备注。保留表外文本和未知列，版本检查/备份、草稿暂存及冲突保留；旧非规范表需先重新生成。
- 采用默认是，空白也默认是。取消父项连同子项取消，采用子项恢复祖先；编号前缀与上级保持一致。取消项保留规划/Excel但不新增实施条目，历史节点不因用户取消而抹除；全取消时提前提示重新勾选。
- 新增功能先讨论边界、验收、技术和准备，每轮少量问题；讨论不写文件，确认后通过生成/更新规划书合并，保留旧编号和取消选择。
