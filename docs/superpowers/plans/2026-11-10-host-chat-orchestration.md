# 宿主对话项目编排实施计划

> 使用并行子 Agent 实现独立模块，集成后由另一 Agent 审核，保留真实验证边界。

目标：用户在 Codex 或 Claude Code 的当前对话完成项目管理，移除网页对话和写入入口。

方案：沿用 Python 标准库、Markdown 文件与纯代码编辑模块。新增共享项目操作服务及 MCP 工具；分析由宿主当前会话或其子智能体完成，工具不调用后台大模型。网页保留粉绿风格的只读项目、规划、台账和记录查看。

本轮用户已明确要求执行此迁移；网页保留只读视图是实施选择。直接让模型改任意 Markdown 会丢失现有版本/历史保护，故采用结构化工具执行。仅删除聊天控件不能提供完整宿主流程，故同步补齐写工具并关闭旧HTTP写接口。

- [x] 新增 ProjectService：项目创建导入、规划保存、功能编辑/采用/建议合并、GitHub调研、源码证据准备与分析提交、台账生成保存、历史、导出；所有写入跨进程锁与版本校验。
- [x] MCP：声明明确工具schema、验证参数、分阶段反馈；无需打开网页即可完成全流程。
- [x] 进度：纯代码更新状态和实施证据；完成必须带独立审核身份、评分理由与证据，保留旧记录。
- [x] 网页：项目总览、规划表/文档/记录、嵌套看板；统一导航，去除全部创建/编辑/聊天写入口，旧HTTP POST拒绝；GET表格与Excel只读。
- [x] 插件：更新两宿主技能/清单/安装与文件说明，构建0.2.0本地包；不覆盖已发布0.1.0制品。
- [x] 验证：临时独立目录的双项目完整MCP流程、源码绑定/过期与并发冲突、保存历史保护、只读网页实际查看、两包独立协议启动；未真实验证的Claude宿主如实保留。

重点边界：跨项目候选拒绝；两宿主并发不能覆盖；预览不落盘；已验收记录不能被AI分析伪造；代码引用必须来自已准备的固定源码；旧浏览器无法继续写入；导出不得覆盖原文件；不修改用户业务数据。
