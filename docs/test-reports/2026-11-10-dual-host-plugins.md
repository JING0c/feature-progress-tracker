# Codex 与 Claude Code 插件验证

日期：2026-11-10。基线：`053d017`；工作分支：`feat/dual-host-plugins`。在新开发副本实现插件，不修改旧服务使用的项目数据。

## 交付范围

- 两套宿主插件清单、项目管理技能、stdio MCP 服务和本地插件市场。
- 两个自包含插件 ZIP，以及可解压后直接注册的完整市场 ZIP。构建只纳入运行代码、技能和安装说明；不纳入项目资料、测试数据或凭据。包内文件有 SHA-256 清单。
- MCP 打开指定管理器、列出登记项目、读取规划书和台账。网页选择对应宿主 CLI 做分析，确定性操作继续用已有代码校验。
- 管理目录保存用户 Markdown；插件安装缓存仅保存程序。每个管理目录只有一个插件服务可写，切换宿主需要停止已核验实例。

## 实际验证

1. Codex `0.166.0-alpha.6`：从完整市场 ZIP 解压到带空格的临时目录，以独立 `CODEX_HOME` 注册本地市场、安装插件。真实 Codex app-server 发现版本 `0.1.0` 的三个 MCP 工具，`toolsError=null`；分别实际调用 `list_projects`、`read_project`、`open_dashboard` 成功，最后停止测试服务。未改变用户全局插件配置。
2. 双插件制品：分别从 ZIP 解压并按包内配置启动真实 stdio MCP 进程，完成 initialize、tools/list、项目读取、打开网页。项目页与规划页 HTTP 200，宿主文案匹配；按顺序切换宿主后，登记、规划与台账文件字节保持一致。此项验证的是本地服务和协议，未调用模型。
3. 只读和实例边界：不存在的管理目录不创建文件；无效项目编号拒绝；项目文件位于插件缓存时拒绝；端口被占用时另选空闲端口，原监听器保持；错误宿主不能停止服务；元数据损坏不能绕过服务生命周期锁；插件更新后提示重启旧服务。
4. AI 适配：受控的真实 CLI 子进程测试覆盖成功/错误 JSON、空回复、超时、取消、缺失 Claude 不回退 Codex、跨项目上下文、生成后按现有门槛保存。Claude 子进程按官方 Agent SDK 的方式仅清理 `CLAUDECODE` 宿主标记，保留认证/权限环境，禁用工具和 MCP。Codex 真实 CLI 预检证实枚举并禁用独立 MCP，再检查全部禁用后才运行分析。

## 独立审核发现与修复

审核者：`/root/plugin_independent_review`，与三个实施者不同。

- 首轮复现同一工作目录两个宿主同时保存可能互相覆盖。改为共享启动状态和服务生命周期文件锁；独立并发启动实测只有一个成功，损坏状态文件也无法启动第二个服务。
- 首轮发现 Codex 的只读沙箱不等于独立 MCP 工具禁用。加入真实 CLI 枚举、逐项禁用与失败关闭的预检，不改变全局配置。
- 首轮发现停止网页进程会遗留独立 AI 子进程。需要取消分析并等待请求完成后退出；已加入全分析取消登记、SIGTERM/SIGINT温和退出和请求线程收尾；独立按同一路线复验，0.54秒停止、子进程消失、规划字节不变。另有空闲HTTP连接不能无限拖住退出的回归。

## 验证边界

- 本机未安装 Claude Code，未进行真实 Claude 宿主安装、登录后模型生成或服务端计费调用。Claude 的成功内容来自明确的受控进程夹具，不能作为模型质量证据。
- 本轮 Codex 验证了真实宿主安装、工具调用与 CLI 安全预检，没有请求真实模型重新生成规划。
- 未改动用户真实项目，未进行新的逐屏浏览器体验验收、Windows 测试或远程市场发布。现有页面行为回归与本地 HTTP 验证不等同真机全流程验收。
- 传统手工启动的 `serve_dashboard.py` 不参与插件实例锁；应先关闭旧服务，避免多个服务同时编辑同一项目。
